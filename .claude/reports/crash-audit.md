# Ferry 崩溃类问题排查（2026-11-01）

起因：0.13.29 里发现 `ferry ai-exec` 的进度回调绕圈，进程把内存用完后崩溃。这次把同类问题、以及其他会让程序崩溃或卡住的问题，在全项目里排查了一遍。

## 怎么查的

1. **同类问题**：找所有「临时换掉共享对象」（`e.Rep`、`e.Yes`……）的地方，以及回调里又用到这个对象的地方。
2. **并发**：确认每个请求是不是各用各的引擎；在 Linux 容器里跑全部测试的竞态检测（`go test -race`）。
3. **静态检查**：staticcheck。
4. **模糊测试**：解析外部输入的函数（dnf / apt 的输出、`semanage`、nginx 配置、防火墙规则、AI 写的模板、模型给的命令、ferry.yaml），每个用随机输入跑 30～40 秒。
5. **按类别人工排查**：
   - 没有兜住 panic 的后台 goroutine；
   - 没有退出条件的循环；
   - 没有上限的读取、输出缓冲；
   - 指数增长的展开；
   - 越界取值。

## 结果

竞态检测：22 个包都通过，没有数据竞争。staticcheck：只有命名风格、没用到的函数这类，没有真正的问题。模糊测试：没有崩溃。没有退出条件的循环：33 处都有退出条件。

下面是查出来、已经修好的问题。「致命」的意思是 Go 拦不住，进程直接退出。

| # | 问题 | 后果 | 怎么修 |
|---|---|---|---|
| 1 | `ai-exec` 的进度回调用了被临时换掉的 `e.Rep`，进度在里面绕圈（已在 0.13.29 修复） | 致命：内存用完。经 MCP 让 Ferry 装软件时必崩 | 回调用换之前的那个 |
| 2 | AI 写文件前读原文件算差异，读多少没有上限 | 致命：模型给出 `/dev/zero`、几 GB 的日志等路径时，桌面版后台进程内存用完 | 只读普通文件，最多 2 MB；更大的不显示差异 |
| 3 | 模板里 `${random:N}` 的 N 没有上限 | 致命：AI 写成很大的数时，一次申请几 GB 内存 | N 限制在 1～1024；模板检查时就拦下 |
| 4 | 模板变量在参数里层层重复引用时，展开后的长度成倍增长 | 致命：内存用完 | 展开后超过 4 MB 就报错 |
| 5 | ferry.yaml 的变量同上（层数有限制，长度没有） | 致命：内存用完 | 展开后超过 1 MB 就报错 |
| 6 | 检查命令是否只读时展开 `{a,b}`：限制了层数，没有限制每层多少项 | 致命：一条命令能展开出上亿个词 | 先算会展开成多少个，超过 256 就不展开 |
| 7 | 服务器上 agent 执行命令（`Shell`）的输出全部攒在内存里 | 致命（服务器上）：输出没完没了时 agent 被杀，撤销步骤来不及执行，留下装了一半的软件 | 只留最后 8 MB |
| 8 | 同上：超时只杀 `sh`；命令留下的后台进程占着输出时，一直等下去 | 卡死：一直占着安装锁 | 放进单独的进程组，超时整组杀掉；命令结束后最多再等 5 秒 |
| 9 | 「经这台电脑下载」的代理跑在桌面版后台进程里，它的 goroutine 没有兜住 panic | 一处出错，整个桌面版后台退出（终端全断、部署断线） | 加上兜底，只断这一条连接 |
| 10 | 发部署通知的 goroutine 没有兜住 panic | 同上 | 加上兜底，算作这条通知发送失败 |
| 11 | MCP 工具出错（panic）没有兜住 | ferry mcp 退出，编程软件里 Ferry 的工具全部断开 | 每次调用加兜底，只让这一次失败 |
| 12 | agent 没有最外层的兜底 | 本机只看到「agent 没有返回结果」 | 返回明确的失败结果（各步骤的撤销照常执行） |
| 13 | agent 探测软件源、读钩子输出的 goroutine 没有兜住 panic | 这种 goroutine 一出错，主流程的撤销都来不及执行 | 加上兜底 |
| 14 | 构建输出里用 `\r` 刷新的进度（不换行）一直攒着；`prefixWriter` 每次写入都把整个缓冲转换一遍 | 内存慢慢涨，越来越慢 | `\r` 只留最后一次刷新的内容；超过 64 KB 不换行就先输出 |

## 新加的测试

- 模糊测试：`internal/agent`、`internal/swtpl`、`internal/ai`、`internal/config` 各有一个 `fuzz_test.go`。平时 `go test` 只跑种子用例；要深入跑用 `go test -fuzz`。
- `TestRealShell`（只在 Linux 上跑）：后台进程不会卡住、超时会连子进程一起杀、输出太多只留最后一段。
- 各种展开爆炸、输出缓冲、随机串长度上限都有测试。
- e2e：经 ai-exec 装软件、升级、恢复、设置备份。

## 还没覆盖、以后可以做的

- 模糊测试只跑了几十秒。可以在 CI 里定期多跑一会儿。
- 桌面版前端（Vue）没有做同样深度的排查。任务输出、日志窗口都有行数上限，其他地方没有逐一查。
