# 查看应用运行情况

在项目应用卡片或列表中，打开「更多 → 查看运行情况」。详情按需从当前服务器读取，支持刷新、搜索、复制详情；绝对路径可以点「查看位置」叠加打开服务器文件浏览器，关闭文件抽屉后继续查看原来的运行详情，保留搜索和滚动位置。应用的查看位置、日志、版本等操作统一从「更多」展开。

详情包括进程 PID、运行用户、实际命令行、工作目录、线程和常驻内存，systemd 当前加载的启动命令、服务文件、覆盖配置、环境变量文件路径、重启策略，以及部署目录、产物、数据、日志、当前版本、提交和健康检查。常见命令行密码参数会隐藏，不读取进程的环境变量值。

不同应用类型还会显示：

| 类型 | 运行环境信息 |
| --- | --- |
| Java（JAR） | 实际 Java 程序和目录、版本、JDK 发行商与架构（有 release 文件时）、JVM 动态库；支持识别包装脚本启动的 Java 子进程 |
| 前端静态站点 | 已发布绑定的 Nginx 实例、登记版本、实际程序和版本、安装目录、主配置、prefix、站点配置目录、本站点配置、域名、监听和静态文件位置 |
| Python | 实际解释器和版本、项目虚拟环境、虚拟环境真实目录与 pyvenv.cfg 信息、依赖缓存目录 |
| Node.js | 实际 Node 程序和版本、node_modules 及其实际链接位置、依赖缓存目录 |
| .NET | 实际启动程序、加载的 CoreCLR 路径和可识别的运行时版本、runtimeconfig.json 声明的目标框架与运行时要求；不将 SDK 版本当作运行时版本 |
| 原生程序 | 实际可执行文件和位置；Go 程序在可读取构建信息时显示 Go 编译器版本和主模块，不执行应用自身猜测版本 |

运行环境以进程信息为依据，服务命令以 systemd 当前加载的配置为依据。服务停止时，显示已加载配置或当前部署版本保存的配置；尚未部署的内容会标明来自当前项目配置，不会将配置值当成已经运行的事实。仅发布文件、手动接入 Web 服务器的站点，显示能够确认的站点文件与检测说明，不猜测它使用的 Nginx 实例。

查看详情不部署或启停应用。为读取解释器版本，只对已识别的 Java、Python、Node.js、Nginx 运行进程执行固定版本参数，非 root 进程使用其运行用户；原生应用和 .NET apphost 不执行版本命令。

兼容旧版 systemd（包括 CentOS 7 的 219）：请求中有不支持的可选属性时，仍使用返回的有效服务属性，并兼容 `EnvironmentFile` 的旧名称；不会因缺少自动重启次数等字段而丢弃全部服务信息。读取进程程序入口的版本失败时，只在核对磁盘文件与该运行进程为同一个可执行文件后，才以运行用户改用文件路径读取；文件已替换、进程退出或实际读取失败时显示具体原因，不把其他版本当成正在运行的版本。

## 切换运行环境

在应用卡片或列表中点「更多 → 切换运行环境」，也可以从运行情况窗口顶部的「更多」进入，按应用类型检测服务器现有的 JDK、共享 Nginx、Python、Node.js 或 dotnet 主机。列表显示版本、绝对路径、来源和当前使用标记；没有执行权限、版本验证失败或尚未启动的 Nginx 会显示不可选原因。

选择后可查看配置差异，并选择「仅保存配置」或「保存并部署」。保存只新增或替换 `targets.<服务器>.appRuntimes.<应用>`，不会覆盖其他服务器或应用的运行环境。保存并部署会将当前应用及服务器带入现有部署审阅，使用当前本地产物重新部署；开始前可以查看代码及配置变化，仍保留生产确认、预检、健康检查和失败回滚。取消部署时，已经保存的选择仍在配置中，实际进程不会因此改变。

Python 使用所选解释器创建新的虚拟环境；Node 服务与依赖安装使用同一 Node，依赖缓存也区分所选程序。Nginx 迁移只移动本站点配置并重载相关实例，不停止共享 Nginx；迁移检查、重载或健康检查失败时恢复原站点、绑定和运行版本。不同实例不能同时监听相同地址和端口，原端口被其他站点共用时，可以在切换窗口更改本站点端口。

Nginx 的完整主配置由服务器上的 root agent 校验，避免普通 `runuser` 丢失 systemd 的低端口绑定能力，将实例已有的 80、81、443 等监听误判为配置错误。校验前会为本站点准备归运行用户所有的日志文件；不截断已有日志，也不修改 Nginx 服务的运行用户。迁移回滚时一并恢复原实例用户对站点日志的所有权。应用列表和运行详情按实际当前版本与绑定显示，待部署的选择不会覆盖已回滚的运行状态。

原生程序没有独立解释器，应通过「版本 / 回滚」切换程序版本。.NET apphost、自带运行时程序以及无法独立替换解释器的包装脚本会说明限制；dotnet 主机下具体使用的兼容运行时版本仍由应用的 `runtimeconfig.json` 决定。

例如，只为 prod 上的 api 选择已经安装的 JDK：

```yaml
targets:
  prod:
    appRuntimes:
      api: {java: /opt/jdk-21/bin/java}
      web: {nginxInstance: edge, port: 8090}
      worker: {python: /opt/python-3.12/bin/python3}
      node-api: {node: /opt/node-22/bin/node}
      dotnet-api: {dotnet: /opt/dotnet-8/dotnet}
```

命令行同样可用：

```text
ferry app-info prod api -c /path/to/ferry.yaml
ferry app-info prod web -c /path/to/ferry.yaml --json
ferry app-runtimes prod api -c /path/to/ferry.yaml --json
```
