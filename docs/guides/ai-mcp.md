# AI 助手与 MCP

## AI 助手

- 在项目或连接里用大模型查看、排查服务器。可以在「设置 → AI」里配置多个模型：Anthropic，或者 DeepSeek、通义千问、内网模型等 OpenAI 兼容接口，各自的 API Key 存在系统凭据库里。
- 对话时可以换模型、选思考强度；回答边生成边显示，显示 token 用量和估算费用；可以改某句话重新发，可以导出成 Markdown。
- 能看图片的模型（Claude、通义千问 VL、GPT-4o 等）可以附图片：直接粘贴截图、点图片按钮选文件，或把图片拖进输入框，大图会先缩小。按模型名认不准时，在模型设置的「图片」里改。
- **只读诊断**：自动运行 Ferry 的固定诊断命令（磁盘、内存、在线时长、内核与架构）以及项目的结构化查看工具。AI 和 MCP 查看工具不会自动安装服务器端 Agent。需要组件时，先在 Ferry 中手动连接并完成安装。
- 应用状态不对、任务失败时，点「让 AI 看看」：把状态、日志、出错的步骤带给助手，直接开始排查。
- **数据共享**：对话、图片和工具结果会发送给当前模型。首次默认关闭日志、配置和数据库查询明细，勾选后才让助手读取并发送这些明细。本机会按项目和服务器记住开关状态。脱敏覆盖常见格式。已有对话可能包含此前分享的内容。
- **逐项确认**：打开「允许改动」后，助手可以申请执行自定义命令、编辑文件、部署、启停、回滚、安装软件或修改网络配置。卡片显示目标、操作内容和影响。失效或不匹配的确认需要重新发起。回滚卡片显示具体版本，写文件会核对预览时的文件版本并保留备份。
- **自动确认**：非生产目标可以在助手顶部选择黄色（启动、重启应用）和红色（停止应用），本机会按项目和服务器记住。开启「允许改动」后，用「重启应用 api」这样的消息直接指定一个 Ferry 自管应用，每条消息最多自动确认一次。自定义命令、对外探测、删除和数据库改动逐项确认。自动确认会记进对话和审计。
- **密码不经过模型**：要你提供密码、账号时，助手在对话里弹出输入框让你填；你也可以点输入框下面的锁形按钮「安全输入」。填的内容只交给这台电脑上的 Ferry，模型只拿到代号（如 `{{secret:mysql_root}}`），执行时 Ferry 才换成你填的内容：命令里经 SSH 的标准输入设成环境变量 `FERRY_SECRET_<名字>`（不出现在服务器的命令行、进程列表里），写文件、装软件的参数里直接替换。用到这些值的命令每次都要你确认；命令输出交回模型前，出现这些值（或它们的 base64）的地方换成 `******`。默认只记在内存里，Ferry 退出就忘掉；勾选「记住」存进系统凭据库，在「设置 → 凭据」里能查看、删除。
- 改动记在本机的 `ai/audit.jsonl` 和服务器的系统日志里（`journalctl -t ferry-ai`），里面都只有代号。发给模型前还会遮住常见格式的密码、密钥。
- **项目配置**：助手能查每个配置项是什么意思、怎么写（`config_schema`，和表单、补全用的是同一份说明），看现在怎么写的（`config_get`）；允许改动时用 `config_edit` 按路径改 ferry.yaml 或这台电脑的本机设置，只改要改的那几行（注释、空行、写法照旧），改完先校验，给你看差异，同意后写入，下次部署生效。见下面 MCP 里的 `config_edit`。
- 「允许改动」首次默认关闭，本机会按项目和服务器记住开关状态。`production: true` 的项目目标每次打开助手都从「只读」开始，部署由用户在 Ferry 界面操作。`aiChanges: false` 禁止使用 AI 改动工具。

## MCP（接入编程软件）

`ferry mcp` 让 Claude Code、Cursor、VS Code、Codex 等编程软件查看 Ferry 里的项目，以及服务器上应用的状态、日志、版本、部署记录、已装的软件、端口、登录用户、告警和数据备份。

- 查看的工具，直接执行：
  - `list_projects`（含这台电脑上缺的私钥、源码目录）、`app_status`（含「谁正在部署」）、`app_logs`、`app_releases`、`deploy_history`（谁做的、启动用了几秒）、`server_software`、`server_ports`（端口谁在用、防火墙放行了哪些）、`server_info`（CPU、内存、挂载点）、`app_info`（实际运行环境与部署位置）、`app_log_runs`（历史运行日志）、`files_list`/`files_preview`/`files_size`/`files_access`/`files_download`（目录、文件内容、大小、权限、下载到本机）、`keep_scan`（部署时保留的文件）。
  - `deploy_changes`：部署前看这次会带上线的提交、改了的文件、systemd 单元和附带文件的变化；线上有本地没有的提交时提醒。
  - `monitor_status`：服务器告警开没开、上次检查发现的问题；`check` 时现在检查一次（不发告警）。`backup_status`：数据备份开没开、各项上次的结果、有哪些备份文件。
  - `server_check`：能不能连上、网络延迟（连不上时说明原因）；`port_check`：从这台电脑测服务器的端口实际能不能连上；`ssh_sessions`：谁连着服务器（登录用户、来源 IP、在干什么）。这三个「新建连接」的服务器也能用。
  - `preflight`：部署前检查服务器环境（只检查不改）；`software_logs`：服务器上软件（MySQL、Redis……）的日志。
  - `db_connections`、`db_schema`、`db_query`：「数据库」里保存的连接、库表结构、只读查询。只能用你在连接上勾选了「允许 AI 查询」的（默认不勾），密码要记住在凭据库里（或是 Ferry 装的软件）。查询一次一条，只读事务里执行，最多 15 秒、500 行；`SELECT … INTO`、加锁、`SLEEP`、读写服务器文件、结束别人连接的函数、账号密码表都拒绝。Ferry 的 AI 助手里也有这三个，只对着当前服务器上的连接。
  - `db_execute`：改数据、建表改表。只能用你在连接上另外勾选了「允许 AI 修改」的（只读的连接不能勾），和部署一样要打开「允许编程软件请求改动」，经生产服务器连的不行。每次都在 Ferry 里弹出完整的 SQL 和危险提示（没写 WHERE 的 UPDATE / DELETE、删表、删列），不给「不再询问」；同意后在一个事务里执行，有一条失败就全部撤回（MySQL 的建表改表撤不回，确认框里会说明），等锁最多 10 秒。不能建库删库、动账号权限（GRANT、CREATE USER）、SET、CALL、LOAD DATA、COPY、能执行系统命令的函数。Ferry 的 AI 助手在允许改动的模式下也有，每次在对话里确认。
  - `redis_query`、`redis_execute`：Redis 连接（同样要勾选「允许 AI 查询」「允许 AI 修改」）。`db_schema` 列出有键的库和键；`redis_query` 执行一条只读的命令（按 Redis 自己的只读标记判断，最多 15 秒，回复像 redis-cli 那样排好）；`redis_execute` 一次最多 100 条改动的命令，确认后用 MULTI/EXEC 一起执行（Redis 没有回滚，确认框里会说明）。`KEYS`、`CONFIG`、`ACL`、`CLIENT`、清库、切库、脚本、会一直等的命令都不给用。
  - `run_command`：运行 Ferry 的固定诊断（磁盘、内存、在线时长、内核和架构）。应用日志和端口使用相应工具。
  - `build_log`：本机构建的完整输出（构建失败时看编译错误）。
  - `detect_project`：识别目录里的应用（新建项目前用）。
  - `software_templates`、`template_guide`：软件模板库（含每个模板能补充哪些配置）、模板的格式。`software_install` 的 `extra` 写模板参数没有的设置。
  - `config_schema`：有哪些配置项、每项是什么意思、起什么作用、怎么写（类型、可选值、默认值、是否必填、只对哪类应用有用、和别的项的关系）；按路径一级一级看（如 `apps.[].service`），或按关键字搜（如「健康检查」「jvm」）。和桌面版表单、补全用的是同一份说明（`desktop/src/editor/schema.ts` 导出的 `internal/config/schema.json`）。
  - `config_get`：项目配置现在怎么写的（整个文件，或某一项的原文和展开 `<<`、`*` 之后的值），以及现在校验出的问题；`scope: local` 看这台电脑的本机设置。
  - `config_check`：校验配置不写入：现在的文件、编程软件自己改好的内容，或者试改（返回差异）。
- `config_edit`：按路径增删改 ferry.yaml（`scope: local` 改这台电脑的本机设置：私钥、登录方式、变量在这台电脑上的值），一次可以改好几处（`set` / `delete` / `append`）。要打开「允许编程软件请求改动」，每次都在 Ferry 里确认：
  - 只改要改的那几行，注释、空行、写法照旧；对象的键按表单里的顺序写。改完重新解析、核对和要改的完全一致才写；核对不上（锚点 `&`、别名 `*`、合并 `<<` 用得特别的地方）就不改，请你直接改文件。
  - 改完先校验，不通过不交给你确认，直接把问题告诉编程软件让它改。确认框里是差异和改到了哪些项；改了部署时执行的命令（hooks、构建命令、启动命令、备份命令）、服务器的登录方式和部署位置、删掉了应用 / 服务器时标红。
  - 你同意时文件又被改过了就不写。生产服务器、`aiChanges: false` 的服务器的配置，以及 `production`、`aiChanges`、`deployers` 这几项，只能你在 Ferry 里改。
  - 命令行：`ferry config-schema [<路径>] [--query <关键字>]`、`ferry config-get [<路径>] [--local]`、`ferry config-edit [--local] [--dry-run]`（修改在环境变量 `FERRY_CONFIG_EDIT` 里）。
- 改动的工具：`deploy`（先在本机构建）、`app_control`（启动 / 停止 / 重启）、`rollback`。默认关闭，在「设置 → 命令行与 MCP」里打开「允许编程软件请求部署、启停、回滚等改动」后才能用，可以只允许勾选的服务器：
  - 每次都在 Ferry 桌面版里弹出确认：哪个编程软件、项目、服务器、它给的理由，部署时还有代码的分支和提交（有没有没提交的改动）、构建命令、线上现在的版本；回滚时是从哪个版本回到哪个版本。
    点「同意执行」才做；5 分钟没确认、或 Ferry 没打开时一律不做。
  - 同意后由桌面版当作普通任务执行：任务面板里看得到过程、可以停止；结果（失败时含构建输出的最后几十行）交回编程软件。部署记录里的操作人标成「iron@电脑（经 Claude Code · MCP）」。
  - 拒绝时可以选「这次连接不再接受改动请求」。刚拒绝过的同样请求 2 分钟内再来直接拒绝。
  - 这几个工具一次最多等 40 秒：没结束时返回 id 和进展，编程软件用 `task_status` 接着查（编程软件对一次调用有超时，等确认、构建都可能比它久）。
  - 生产服务器（`production: true`）和 `aiChanges: false` 的服务器始终不允许。
  - 确认默认在桌面版里做：桌面版的 `ferry serve` 在 127.0.0.1 的随机端口上收请求，端口和令牌写在数据目录的 `mcp/approver.json`。编程软件通过此连接提交请求和接收进展。
    要执行的命令由桌面版按请求里的操作、服务器、应用自己拼。桌面版收到请求时也按设置和配置再检查一遍。
- `software_control`：启动 / 停止 / 重启 Ferry 在服务器上装的软件，和部署一样要打开开关、每次确认。
- `port_control`：用防火墙放行 / 关闭端口，和部署一样要打开开关、每次确认（不能勾「不再询问」）。
- `firewall_enable`：打开装了没开的防火墙（先放行 SSH 端口和指定的端口；确认框里列出打开后外部连不上的端口）；`ssh_disconnect`：断开服务器上的 SSH 连接（确认框里列出是谁、从哪里来、在干什么）。都要打开开关、每次确认（不能勾「不再询问」），只能用于项目里的服务器。
- `backup_run`：现在备份一次（一项或全部），和部署一样要打开开关、每次确认。打开 / 关闭告警和数据备份、恢复、删掉备份只能在 Ferry 里做，编程软件做不了。
- 和 AI 助手同一套的改动工具，都要打开开关、每次确认（不能勾「不再询问」），确认框里的内容由桌面版按参数算（危险命令标红、写文件显示和原文件的差异）：
  - `run_change_command`：执行改动服务器的命令（固定诊断命令可直接执行）；`write_file`：写文件，先核对预览时的版本并备份原文件；`software_install`：用软件模板装软件；`save_software_template`：保存软件模板。
  - `ask_secret`：要你提供密码、账号时，Ferry 弹出输入框让你填，编程软件只拿到代号 `{{secret:名字}}`，在命令里用环境变量 `FERRY_SECRET_<名字>`、在文件内容和装软件的参数里写代号，执行时由桌面版换成你填的内容，交回编程软件的输出里遮住。填的内容只记在这次打开的 Ferry 里，按编程软件的这次连接分开。
- **确认方式（桌面端或编程软件内确认）**：
  - 默认每次改动由用户在 Ferry 桌面端逐项确认。
  - 在「设置 → 命令行与 MCP」里可以选择「优先在编程软件里确认」，免去来回切换窗口：
    - **确认渠道按能力自动选择**：支持 MCP Apps（`io.modelcontextprotocol/ui`）的编辑器直接内嵌带差异高亮和实时进度的交互确认卡片（按钮通过 `visibility: ["app"]` 专属工具提交，AI 不可见也无法伪造）；其次使用 MCP 表单（Elicitation Form，默认不勾选，等待期间自动发送进度心跳防超时，秒回自动降级保护）；不支持卡片和表单的软件默认自动切回 Ferry 桌面端，也可勾选开启「两段式确认」（先返回完整预览和 `approvalId`，再由 AI 带着一字不差的 `target / action / danger` 核对参数调用 `confirm_change` 触发客户端原生工具确认栏）。
    - **范围与高危兜底**：默认仅常规运维（部署、启停、回滚、启停软件、运行定时任务、立即备份）在编程软件里确认，可切换到「全部允许的改动」；默认开启「命中高危（危险命令、无 WHERE 删改、改构建/钩子命令等）时仍在 Ferry 桌面端确认」。密码输入（`ask_secret`）、生产服务器（`production: true`）和 `aiChanges: false` 始终严格受限。
    - **桌面端运行与离线执行**：Ferry 桌面端打开时，由桌面端先做权威预检并锁定 TOCTOU 快照（`AIState`/`AIScope`/`Base`/`DBCheck`），用户在编程软件确认后由桌面端在后台静默进任务面板执行（不抢焦点、可随时停止）；桌面端未打开时，仅必须在桌面端确认或执行的操作（填密码、高危拦截、多台灰度暂停部署等）才提示先打开 Ferry，可在编程软件里确认执行的操作由 `ferry mcp` 直接执行并同样写入审计和调用日志。

- `create_project`：新建项目（Java、Go、前端、Python、Node 服务端、.NET 都行）。确认框里显示要写入的 ferry.yaml（由桌面版按内容生成，已有文件不会覆盖），同意后生成文件、加进项目列表；不连服务器、不部署，不需要打开上面的开关。
- 提示（编程软件里可以直接选的命令）：`diagnose` 排查应用故障、`check_after_deploy` 部署后检查。
- 不经确认只能执行固定诊断和结构化只读工具。返回前遮住密码、密钥；每次调用和改动的结果（同意 / 拒绝）记在本机的 `mcp/calls.jsonl`，「设置 → 命令行与 MCP」里点「查看调用记录」，在单独的窗口里按时间、编程软件、操作、成功与否、关键字筛选（`ferry mcp-log`）；保留多少天、最多占用多少在「设置 → 存储」里设置。旁边的「MCP 工具列表」列出编程软件能用的全部工具：作用、参数、是否要你确认（`ferry mcp-tools`）。
- 各软件的接入配置在桌面版「设置 → 命令行与 MCP」里一键复制。
